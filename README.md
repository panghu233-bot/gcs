# GCS 0.7.1 · 已应用对白从备份恢复

《指日可待》的事件编辑器新增「从备份恢复」，与仅处理内存草稿的「撤销未应用修改」分开。用户手动选择已有 `gcs-event-backup-*` 目录，浏览器不会搜索备份历史。读取并核验 `restore.json` 的格式、事件 ID、固定源路径、文件名、原始字节数与对白索引，严格解析备份中的七句对白。逐字节比较七个对白字符串以外的全部源码；注释、换行、说话人、表情、其他事件或结构有变化时拒绝自动恢复。

界面完整展示每句变化的当前对白与备份对白。先选择项目外目录，为当前版本创建并读回校验新备份，再主动点击「授权恢复对白」。恢复只通过原有对白字符串补丁写入，不覆盖整份备份文件；提交前再次检查当前源码、执行入口、所选旧备份和新备份，暂存后再查冲突。恢复后逐字节读回、重新解析七句并自动刷新当前对白。失败沿用原有安全回滚与写入锁定；其他程序写入的新内容不会被自动回滚覆盖。最后检查与提交之间仍存在浏览器无法消除的短暂并发窗口。

人工恢复验收（待用户执行）：

1. 关闭游戏及相关源码编辑器，在 Chrome / Edge 打开网站、连接游戏项目，进入剧情事件 → 指日可待。
2. 先应用或撤销未应用修改，点击「从备份恢复」，选择需要恢复的具体 `gcs-event-backup-*` 子目录（内有 `restore.json` 和 `cultivation_data.gd`）。
3. 检查完整差异；遇到非对白变化或校验错误时停止，保留备份供人工核对，勿直接整文件覆盖。
4. 点击「选择项目外目录并备份当前版本」，选游戏目录之外的位置，确认备份已验证。
5. 点击「授权恢复对白」，完成浏览器写权限授权；确认恢复成功、七句重新解析且当前对白已刷新。
6. 点击重新读取再次核对，然后启动游戏验证对白。若要撤销本次恢复，再通过「从备份恢复」选择第 4 步生成的新备份，重复审阅、备份和授权。

本轮仅修改事件写入器、事件界面、定向测试、版本及发布文档/压缩包，未修改卡牌或 NPC 模块。16 项事件定向测试通过，包含模拟 DOM 的完整恢复流程、权限拒绝、取消、草稿保护、自动刷新，以及合成 GDScript/内存文件系统的备份篡改、非对白差异、冲突和失败回滚。全部网页脚本语法检查通过。未读取或写入真实游戏内容，未执行真实恢复；原生目录选择、浏览器权限和游戏内恢复效果待人工测试。部署结果以本次交付报告为准。

## 0.6.0 NPC 现有立绘替换

在真实 NPC 的「人物形象」或概览中选择已有立绘版本，点击「更换图片」并选择电脑上的 PNG。对话框显示原图、新图、原资源路径及共用此资源的已识别 NPC；此时仅暂存，不会写入游戏。仅支持已加载的现有 PNG，最多 8 MB、单边最多 16384 像素、总像素最多 6400 万，并验证 PNG 分块校验及浏览器解码。不新增版本，不修改映射、路径、GDScript 或 Godot 导入文件。

点击「选择项目外目录并备份原图」，创建独立的 gcs-portrait-backup-* 子目录，逐字节读回校验原图备份和记录原路径的 restore.json。只有备份通过后才能点击「授权写入并替换」，浏览器此时请求游戏目录写入权限。覆盖前、暂存后再次检查磁盘原图，写入后逐字节验证。失败时中止暂存，必要时恢复原图并校验；发现其他程序的新内容时不继续覆盖，显示备份位置和人工恢复提示。自动恢复未完成时，当前图片停止写入，直到检查备份并重新读取项目。

替换成功会更新当前版本与已识别共用此路径的立绘预览和原图快照，无需重新读取整个项目，保留未应用的卡牌草稿。兼容文件列表模式只读，需通过支持目录访问的浏览器重新连接。关闭对比取消暂存；备份不会随取消删除。共用提示范围为当前识别 NPC，游戏其他使用相同路径的位置也受影响。浏览器不能避免最后一次检查与提交之间极短的外部修改竞争，也无法保证断电或磁盘故障后的自动恢复；请先关闭游戏和图片编辑软件。

人工恢复时，先关闭其他编辑器，按备份目录 restore.json 的 path 将同目录原图复制回游戏原资源路径，再在 GCS 重新读取。自动测试仅使用合成 PNG 和项目外临时目录，覆盖备份失败、授权拒绝、外部冲突、单版本替换、写后失败恢复及备份手动恢复；浏览器原生目录选择与真实项目首次写入留待用户验收。私人素材不进入仓库、发布包或网络请求。卡牌模块与写回机制保持原样。

## 0.5.1 保存可靠性修复

本轮不增加编辑功能。保存改用固定版本的 Microsoft `jsonc-parser` 3.3.1，按严格语法树定位用户已编辑的现有标量值，不对整份 JSON 重新序列化。其余原始文本、缩进、CRLF / LF、键顺序、Unicode 转义、UTF-8 BOM 和文件末尾格式保持不变。

保存预检逐一核对适配器可编辑字段、明确修改清单、原始值、目标值、卡牌 / 分支归属和语法树节点范围。只接受值标记范围内的单个替换；不允许插入、删除或自动重建结构。所有补丁应用后重新完整解析 JSON、校验结构与关联，并验证全部数据差异恰好等于授权修改。重复键、编码问题、定位失败或范围外变化一律拒绝写回，绝不回退到整文件格式化。

原有备份、磁盘冲突检查、暂存、逐字节读回验证、撤销及失败回滚继续保留。未改动的另一份文件不会被打开覆盖。

新增测试包括真实 Node.js 文件系统上的暂存、fsync、rename、备份验证和实际备份恢复。项目外真实数据副本的实际差异证据只在本地保留，不把真实卡牌内容放入公开测试或文档。Node.js 磁盘测试不等于浏览器原生目录授权测试；本轮没有尝试或绕过原生文件夹授权。

## 真实卡牌工作台

点击「打开游戏项目」选择游戏根文件夹，自动定位卡牌与升级分支 JSON。「卡牌设计」使用真实列表，中间编辑基础属性，右侧查看与编辑升级数值修正、实时预览。

- 开放现有名称、费用、伤害、格挡、攻击次数、抽牌、寒意、治疗、虚弱、冻结等已确认字段；X 费卡保留其费用规则。
- 特殊分支仅开放已确认的现有数值修正。ID、结构、布尔效果和未知字段保持锁定，普通升级配置保持原样。
- 编辑只修改内存工作副本，提供卡牌 / 字段修改标记、原始值对比、撤销一步、逐字段还原、还原此卡 / 全部、校验与导出工作副本。
- 特殊效果原文、嵌套数据、根节点元数据和原有说明不会被删除或自动改写；分支原说明可能与手动修改的数值不同，界面明确标注。
- 保存前验证格式、整数与范围、ID 唯一性、升级关联、最终数值精度，以及变更是否局限于允许字段。无法无损表示的数字会拒绝载入编辑，不静默舍入未知数据。

内存修改不自动持久化，刷新或关闭前请导出工作副本。导出文件是包含两份文档的单个 JSON 包，未直接写入游戏，也不是演示工作区导入格式。NPC、剧情及演示卡牌的编辑、关联、试读、导入导出与本地暂存继续保留。

## 授权应用与备份

连接和恢复项目只请求读取权限，不会开始写入。只有用户主动点击「应用修改到游戏」，审阅全部差异，选择游戏项目之外的备份目录，再点击「授权写入并应用」后，才请求游戏目录写入权限。

1. 校验工作副本及局部文本补丁，重新读取两份原文件，发现磁盘冲突即停止。
2. 在所选项目外目录新建唯一 `gcs-backup-<随机编号>` 子目录，保存两份原文件的原始字节。读回备份确认完全一致；现有备份不会被覆盖。
3. 只为实际发生变化的原 JSON 准备仅替换授权字段值的写入流；保留其余原始字节。全部准备完后再次比较磁盘原文件，再逐一提交并读回验证。
4. 常规失败时中止未提交的写入，并把已提交文件按原字节回滚。没有完成恢复时显示备份位置并锁定进一步应用，避免无提示重试或覆盖并发修改。

卡牌流程在游戏目录仅允许覆盖适配器声明的两个 JSON，不创建其他文件。备份文件仅在用户明确选择的项目外目录中创建。未改动的 JSON 仍会备份，但不会覆盖。

浏览器不提供两个文件之间的原子事务。断电、磁盘失联、外部同时编辑或回滚本身失败时，可能需要从验证过的备份手动恢复；不能承诺这些故障下自动恢复。建议应用前退出游戏并关闭其他编辑器。恢复时将备份目录内两份原 JSON 放回原 `data/cards/` 位置。

写回需要支持目录写入 API 的浏览器，例如近期 Chrome / Edge。兼容文件夹模式可读取、编辑、校验与导出，但不能直接写回。原有目录句柄记忆、权限检查及一键重新授权保留；权限对话框由用户操作。

## 数据边界

真实数据只在本机浏览器内读取和编辑，不上传、不存入演示工作区，不随网站代码发布。自动记住的只有目录访问句柄。卡牌读取适配器声明的两份 JSON；NPC 另外定向读取养成立绘映射、养成数据、管理器相关规则、养成故事、茶馆对白、养成对白表情路由、专用立绘渲染绑定与敌人定义，并且只读取这些映射明确引用的图片。不扫描其他源码、存档或密钥。本仓库不包含真实游戏数据和私有资源。

开发与自动化测试禁止对真实游戏根目录执行写入。真实数据用于只读解析和内存编辑；写入、备份和故障回滚在一次性模拟文件系统及浏览器沙盒目录中验证。真实项目首次写回由用户验收并主动授权，未声称已完成真实写回。
