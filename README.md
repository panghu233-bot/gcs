# Game Content Studio (GCS) 0.4

网站：https://panghu233-bot.github.io/gcs/

## 打开本地游戏项目

1. 点击「打开游戏项目」，选择游戏根文件夹。
2. 自动定位适配器声明的卡牌和升级分支 JSON，无需逐一选择文件。
3. 点击「卡牌设计」：左侧是真实卡牌列表，中间是基础 / 修正 / 最终属性，右侧是卡牌预览和升级方向。支持搜索与完整原始字段查看。

连接后真实卡牌替换演示卡牌列表；未连接时明确展示演示内容。NPC 和剧情继续使用原有演示工作区，保留编辑、关联、试读、JSON 导入导出和本地暂存。演示人物与剧情的卡牌关联不会被误映射到真实卡牌。

## 本地权限和数据

支持 File System Access API 的浏览器（如 Chrome / Edge）使用系统文件夹选择器，只请求读取权限。通过 IndexedDB 记住目录访问句柄，重新打开时检查授权：允许时自动重读，需授权时点击「重新授权」。浏览器可能要求再次确认权限，网站不会绕过它。

其他浏览器使用文件夹选择兼容模式，自动识别同样的两份文件，下次访问需重新选择整个文件夹。无法持久存储句柄时会明确提示。使用「重新读取」更新磁盘数据；「断开项目」清除句柄记忆和内存数据。

卡牌 JSON 仅在页面内存中读取，不上传、不存入演示工作区、不写回游戏。目录模式只访问声明的两份文件，不遍历项目、读取代码或加载本地美术。兼容文件夹模式只读取匹配路径的 JSON 内容。网站程序和公开演示资源不包含真实游戏数据或私有代码。

普通升级和特殊分支由独立适配器解析，特殊分支不叠加普通升级。未解释效果保留原始字段；预览不执行战斗结算。

## 源码与发布

- `site/`：静态网站与公开演示资源。
- `site/game-project.js`：文件夹连接、只读传输、句柄保存与授权恢复；不包含游戏专属字段。
- `site/ninggu-adapter.js`：独立结构适配器、项目数据路径及升级解释。
- `site/native-cards.js`：复用主工作区的真实卡牌列表、属性与升级预览。
- `tests/`：不含真实游戏数据的定向测试，运行 `node --test tests/*.test.cjs`。
- `site.zip`：与 `site/` 字节一致的发布包，推送 main 后由现有 Pages 工作流测试并部署。

真实文件回归、浏览器实测、截图和本机测试脚本仅本地保留，不提交到公开仓库。浏览器授权对话框由用户操作，自动化测试不操纵 Windows 桌面。
