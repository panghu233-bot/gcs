# GCS 0.8.0 · 多事件剧情编辑器

网站：https://panghu233-bot.github.io/gcs/

连接《凝顾》根目录后，在「剧情事件」选择真实来源。当前游戏只读核对得到 60 项：51 个养成对白/事件源作用域，以及 9 个 Dialogic 时间轴文件。这里的项目数是可审阅的源码范围数，同一事件可能分成多个段落，不代表 60 个独立、已触发的剧情。列表支持按标题、来源标识和已解析对白搜索，明确区分可编辑和只读。

14 个对白段支持完整编辑：指日可待、前夜、夜难成寐、江畔悟剑前后段、严师慈母白天/夜晚、首次授琴、练琴观看①/②（保留源码临时占位标记）、芦苇滩胜败对白、镖局胜败对白。显示名称只作导航；保存身份绑定源码路径、类与函数，不按标题定位。重新连接后会重新识别实际文件和语法，不固定假定存在这些事件。

使用：选择事件 → 编辑剧本 → 修改文字、插入/复制/删除/排序 → 展开演出预览设置说话人、左右人物和表情 → 查看差异并应用 → 选择项目外目录并验证备份 → 授权写入。人物和 PNG 都按本地游戏的真实映射读取；动作表情等预览不支持的配置明确提示，不替换成猜测的画面。没有背景指令的对白段保留原有宿主场景背景；原有首句背景锚点固定在编辑后的第一句。

恢复：在相同事件的编辑模式中点击「从备份恢复」，选择具体 gcs-event-backup-* 目录，审阅真正发生变化的文字、增删、相对顺序和演出字段，再确认恢复。只恢复当前函数，不整文件覆盖，保留其他事件的后续修改。继续兼容旧版指日可待备份。恢复前快照只保留内存，不另建当前版本备份；普通编辑保存仍必须先创建并校验项目外备份。

分支选择、技能检查、战斗跳转、运行参数、动态拼接、事件工厂奖励逻辑、无法确认入口或含歧义注释的来源，以及 Dialogic 时间轴保持只读。展示可直接确认的字面量对白与完整源配置；只读片段不推断运行时顺序，也不执行游戏脚本。无法解析或无字面量对白的项目直接展示源配置及原因，不能授权写入。

安全边界：仅有界读取三个已声明的养成来源、三个入口文件和 timeline/ 下的 .dtl；人物预览沿用现有本地映射。时间轴目录最多 256 项、4 层，每文件 1 MB、累计 8 MB；源码每文件最多 8 MB。所有发现、编辑、预览、备份与恢复都在本机，无网络上传。草稿仅在内存，切换事件、重新读取或离开前有丢弃提醒；演示 JSON 不包含真实剧情。直接写入需要支持 File System Access 的浏览器。

安全写回复用原有机制：身份与路径验证、严格静态语法、草稿审阅绑定、完整源码和入口冲突检测、备份 SHA-256 与逐字节验证、唯一备份目录、仅目标字符串或函数体补丁、提交前复查、写后完整字段回读、失败安全回滚和不确定状态锁定。源码注释、未知字段、分支和运行时表达式不会被静默丢弃。浏览器仍无法消除最终检查与提交之间的并发窗口，编辑前应关闭其他源码写入程序。

验证：自动化短测试覆盖既有指日可待、卡牌、NPC 和新多事件的解析、界面、真实临时磁盘保存、连续保存、结构恢复、跨事件备份拒绝、篡改/冲突/故障回滚。对全部 14 个支持段逐一用真实源码的隔离副本完成结构及四项演出修改、连续两次保存、重新读取、恢复和同文件其他事件后续修改保留，核对 136 次真实立绘读取。正式游戏相关源码哈希保持不变。无界面 Edge 实际加载 60 项来源、26 名 NPC、42 张卡，检查事件切换、编辑、差异、只读源码、真实立绘及模块切换，页面无脚本错误，全部请求仅到本机。

可复现验证：`npm test`；`npm run verify:events -- --project <Godot项目根目录>`。后者只读所指定项目，所有写入均进入系统临时目录内的隔离副本，并在完成后清理。测试与发布包不包含真实对白、PNG、项目副本或私人验证截图。

原生目录选择/权限弹窗与 Godot 内最终播放属于待人工测试；本轮未接管 Windows 桌面，也未修改正式 Godot 源码。无界面浏览器使用同一生产界面和只读目录适配器，隔离磁盘测试使用同一生产写入器，不能等同于原生权限弹窗或游戏播放已验收。
